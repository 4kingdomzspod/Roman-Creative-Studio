## Purpose

This is the single source of truth for how Roman Creative Studio operates. Every system, process, policy, document, and decision framework lives within this Operating System. When in doubt, start here.

This playbook does not contain the details — it contains the map. Every section links to the authoritative document where the details live.

---

## Business Value

- Eliminates "where does that live?" questions
- Enables any team member to find any process in under 2 minutes
- Ensures consistent execution regardless of who is doing the work
- Supports onboarding, delegation, and eventual succession
- Creates institutional memory that outlasts any individual

---

## How to Use This Playbook

1. **Find your phase** — The OS is organized into 12 phases below
2. **Find your topic** — Each phase lists its documents with a one-line description
3. **Navigate to the folder** — All docs live in `docs/` in the GitHub repository
4. **Execute the process** — Every document contains step-by-step guidance
5. **Flag gaps** — If something is missing or outdated, flag it to the document Owner

## Document Governance

**Creating a New Document**
1. Determine which Phase it belongs to
2. Create in the appropriate `docs/` subfolder
3. Use the standard document header (Version, Owner, Review Schedule)
4. Add to this Playbook index
5. Notify Alexander for awareness

**Updating an Existing Document**
1. Make changes in GitHub
2. Increment version number (1.0 → 1.1 for minor, 1.x → 2.0 for major)
3. Update "Last Updated" date
4. Note change in document changelog (if major)

**Retiring a Document**
1. Mark as "Archived" in document header
2. Move to `docs/archive/`
3. Update this Playbook to note the retirement
4. Redirect any links to replacement document
