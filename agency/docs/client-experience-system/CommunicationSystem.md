# Communication System
## Roman Creative Studio — Phase 6, Document 5

---

### Communication Philosophy

Clients should never have to wonder what is happening. If a client sends a message asking "where are we at?" — the communication system has already failed.

Predictable, proactive, professional communication is one of the clearest signals of a premium agency. It is also one of the most underestimated drivers of client satisfaction and referrals.

**The governing rule:** No unpredictable communication. Clients always know what is happening.

---

## Section 1 — Communication Channels

### 1.1 Channel Definitions

| Channel | Purpose | When Used |
|---|---|---|
| Email | All formal project communication | Decisions, approvals, deliverables, updates |
| Video call | Complex discussions, approvals, reviews | Kickoff, design review, staging review, training |
| Phone call | Urgent time-sensitive issues only | Never for routine updates |
| Project dashboard | Progress visibility | Between milestones |
| Async voice/video (Loom) | Detailed walkthroughs | Staging site tour, design explanation |

### 1.2 Channel Rules

**Email is the channel of record.** Every decision, approval, and important communication happens over email. Verbal agreements made on calls are followed up with an email summary.

**No WhatsApp, no Instagram DMs, no text messages for project communication.** These channels create undocumented, untracked, scattered communication that leads to disputes. If a client messages via social: reply once there, then redirect to email.

**Calls are for conversation, email is for documentation.** Never rely on a call conversation for project decisions. Always follow up in writing.

## Section 2 — Response Time Standards

### 2.1 RCS Response Times

| Communication Type | Response Time Standard |
|---|---|
| New inquiry / contact form | Within 4 business hours |
| Client project email | Within 24 business hours |
| Client feedback on a deliverable | Acknowledged within 24 hours; implemented per revision schedule |
| Urgent issue (site down, error) | Within 2 hours for Care Plan clients |
| Non-urgent question | Within 24 business hours |

**Business hours:** Monday–Friday, 9am–6pm (client's timezone)

**Weekend rule:** RCS does not guarantee weekend responses. If a message arrives Friday evening, the client should expect a response Monday morning. This is communicated at kickoff.

### 2.2 Client Response Time Expectations

Set at kickoff and in the contract:

```
"To keep the project on schedule, we ask for a 48-hour turnaround
on approvals and feedback requests.

If we don't receive feedback within 5 business days, the project
timeline shifts accordingly. We'll send one reminder at the 48-hour
mark before flagging a delay."
```

## Section 4 — Update Frequency Rules

### 4.1 Standard Communication Cadence

Clients receive proactive communication at these points — not randomly, not constantly:

```
Milestone-based communication (always):
  - Payment confirmed (immediately)
  - Kickoff recap (within 24hrs of kickoff call)
  - Strategy document ready (for review)
  - Design mockups ready (for review)
  - Staging site ready (for review)
  - Launch confirmed (day of)
  - Training session scheduled
  - 30-day check-in

Between milestones: Only if something changed.
```

**Why milestone-based (not weekly) communication:**
Weekly updates in a design project often communicate nothing useful. "Still working on it" is not reassurance — it raises questions about pace. Milestone-based updates are meaningful: something was completed and the next phase is beginning.

**Exception:** If a phase is running significantly longer than expected, send a proactive mid-phase update:
```
"Quick note: design is progressing well — I want to make sure
the homepage section achieves exactly the right tone before
sending for review. I'll have it to you by [date]."
```

### 4.2 What to Never Do

| Action | Why It's Wrong |
|---|---|
| Send a "just checking in" email | Creates noise without content |
| Leave client without communication for more than 2 weeks | Creates anxiety and distrust |
| Promise a date and miss it silently | Destroys trust instantly |
| Send a deliverable with no context | Forces client to guess what to do |
| Send piecemeal design updates | Creates confusion; wait until phase is complete |

## Section 5 — Communication Tone Standard

### 5.1 Email Tone

| Principle | Implementation |
|---|---|
| Professional | No slang, no excessive exclamation marks |
| Direct | State what you're sending, what's needed, and by when |
| Confident | "I'll have this to you by Friday" not "I'm hoping to maybe..." |
| Warm but brief | Acknowledge the relationship; don't write essays |
| Action-oriented | Every email ends with a clear next step or CTA |

### 5.2 Delivering Difficult News

**When there's a delay:**
- Lead with the fact, not the justification
- Provide the new date immediately
- Own it without excessive apologizing
- Explain the impact (or lack of impact) on launch

```
❌ Wrong: "So sorry, things have been really busy and I know this is
          frustrating but there's been some complications..."

✅ Right: "The design phase is running 3 days past the planned date.
          New delivery date: [Date]. This won't affect the launch
          timeline as we have buffer built in."
```

**When a client request is out of scope:**
```
❌ Wrong: "That's outside what we agreed on and I can't do that."

✅ Right: "That's a great addition — it's outside the contracted scope,
          so I'd handle it as a change order. Here's what that would
          involve: [brief scope + cost]. Want me to put that together?"
```

## Section 6 — Escalation Process

### 6.1 When Escalation Is Needed

- Client is unresponsive for more than 5 business days
- Scope dispute has not been resolved through normal communication
- Client is providing feedback that contradicts approved decisions
- A technical issue has been unresolved for more than 48 hours
- Client relationship has become adversarial

### 6.2 Escalation Steps

**Step 1:** Send a direct, documented email addressing the issue clearly
**Step 2:** Request a call specifically to resolve it ("I think this needs a conversation")
**Step 3:** On the call, reference the contract scope or approved decision
**Step 4:** If unresolvable: refer to contract terms, engage legal if necessary

**Rule:** Never respond with emotion. Escalation communication is calm, factual, and document-referenced.
